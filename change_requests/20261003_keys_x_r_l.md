# Keys: X is bang only, R resets the knobs, startup key map

## Why
- `X` zeroed `controlA`..`controlD` as a side effect of calling `layout.bang()`. Banging threw away
  the wheel settings with no way back except scrolling.
- The key map lived only in `keyPressed()`, so recalling it meant opening the file.

## What / How
- `VUIDisplay.pde` `keyPressed()`:
  - `X` now calls `layout.bang()` and nothing else.
  - New `R` branch zeroes `controlA = controlB = controlC = controlD = 0`.
  - New `L` branch flips `APPLY_BLOOM` (see the bloom change request).
- `VUIDisplay.pde` `setup()`: call a new `printKeyMap()` once, after `initDisplays()`.

## Does this change what appears on screen?
- [x] Yes — `X` no longer resets the knobs, which changes what the displays look like after a bang.
- The startup printout is console-only.

## Dependencies
- [x] No new library, no new asset in `data/`

## Out of Scope
- `1`-`9`, `SPACE`, `Z`, `W`, `H`, `Q` — untouched.
- The `A`/`B`/`C`/`D` wheel-pick keys. Explicitly left as they are by the owner, including `C` and `D`
  reading nothing.
- The unused `int[] displayKey` at `VUIDisplay.pde:124`. Left alone; deleting it is a free refactor
  whenever the owner wants it.
- An on-screen key overlay. Not built this pass.
- `Q` still does nothing unless `RECORD_VIDEO` is true. Left as-is.
